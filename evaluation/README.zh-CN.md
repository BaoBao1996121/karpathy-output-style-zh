# v0.1 定性验证记录

检查日期：2026-10-05 至 2026-10-06 UTC。

## 方法

对本版本和实际读取的上游技能分别提出三个相同请求：

1. 用三句话解释为什么召回率高，最终答案仍可能错。
2. 用无需联网、可本地打开和逐步播放的 HTML，解释 top-k 从 3 增至 6 为什么仍可能漏掉 B 型号的维护周期。
3. 把“向量检索能保证找到所有正确答案，所以只要调大 K 就不会漏答”改得简短准确。

本版本先读取完整技能正文再执行；当时使用初始工作名称，发布前更名为 `karpathy-output-style-zh`。上游试用实际读取 `clear-writing`、`explain-webpage` 及其清晰表达参考文件。两组都是显式加载后的定性试用，不是自动触发测试。模型版本没有可靠记录，未作推断。

最终名称的技能另经发现和显式加载检查；自动选择可靠性没有测量。没有固定随机种子、重复采样、盲评或用户学习效果实验。

## 结果

- 两组三句话解释均符合长度要求，并区分了检索覆盖与答案正确性。
- 两组改写都删除了错误的“保证”，保留“增大 K 可能减少漏检”的有限结论。
- 本版本 HTML 通过 54 项最小 DOM 替身断言，涵盖六个状态、选择数量、证据输出、播放与暂停、终点重播、手动操作、键盘处理、页面隐藏暂停及静态无网络检查。
- 上游试用 HTML 的分步、K 滑条、播放速度、暂停、重播与后台暂停等逻辑检查通过。
- 两个 HTML 并非完全匹配的数据实例：本版本的 B 证据排第 7，上游试用产物排第 8。不能据此比较视觉教学质量或学习效果。
- 两个 HTML 的真实浏览器检查均未完成。浏览器启动受到 socket 权限限制；第二次打开本地示例受到组织访问策略阻止。没有绕过限制，也没有真实浏览器截图。

结果支持把本版本作为有明确边界的社区适配发布，不支持“首创”“比上游更好”或“全面验证通过”的结论。

## 复查命令

在仓库根目录运行：

```sh
node examples/top-k/check-example.cjs
node evaluation/upstream/check_logic.cjs
python demo/verify_demo.py
```

视频检查脚本会重新解码并更新技术报告；它不会自动完成肉眼画面检查。网页的响应式样式、焦点标记和减弱动态样式只是存在性检查，不能替代真实浏览器与辅助技术测试。
